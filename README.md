# ArchConfig

Минималистичный установщик для свежего Arch Linux: `setup.sh` читает `packages.txt` и по порядку выполняет `packages/<name>/install.sh`.
Каждый пакет сам отвечает и за установку через pacman/yay, и за свой конфиг.

## Запуск

Для полностью чистой системы:
```bash
sudo pacman -Syu --needed git
git clone https://github.com/Teru3301/ArchConfig.git ~/ArchConfig
cd ~/ArchConfig
./setup.sh
```

Если репозиторий уже клонирован:
```bash
cd ~/ArchConfig
git pull
./setup.sh --dry-run   # посмотреть план, ничего не устанавливая
./setup.sh
```

## Структура

```
setup.sh                # главный раннер
packages.txt            # список имён папок в packages/, в порядке установки
lib/common.sh           # общие функции (log_*, pkg_install, link_config)
packages/               # пакеты устанавливаемые скриптом
  {package}/install.sh
```

## Как это работает

1. `setup.sh` читает `packages.txt` (пустые строки и `#` игнорируются)
2. Для каждого имени `name` ищет `packages/<name>/install.sh`
3. Выполняет его с `cwd = packages/<name>` и переменной окружения `PKG_DIR`
4. Если скрипт завершился успешно — помечает `<name>` в `.installed` (лежит рядом с setup.sh)
5. При повторном запуске уже отмеченные пакеты пропускаются (если не `--force`)

Флаги:
- `--dry-run` — показать, что будет выполнено, без выполнения
- `--force` — выполнить все пакеты заново, даже отмеченные
- `--only=NAME` — выполнить только один пакет

## Важные отличия от cp -r

`link_config` делает **hardlink** для каждого файла (не symlink и не copy). Файл в `~/.config/<name>/...` и файл в `packages/<name>/config/<name>/...` физически — один и тот же файл на диске (общий inode), просто с двумя именами. 

### Плюсы:
- правки с любой стороны видны сразу же (это буквально один файл)
- если удалить папку со скриптами (`packages/` целиком) — конфиг в `~/.config` не пропадёт и не станет битой ссылкой, он останется цел, пока жива хотя бы одна ссылка на inode
- если в `~/.config/<name>` уже что-то было — делается backup `<file>.bak.<timestamp>` перед заменой, ничего не удаляется молча
- старая схема (symlink на каталог, если репозиторий ставился раньше) автоматически конвертируется в hardlink'и при следующем запуске

### Ограничение: 
hardlink работает только в пределах одной файловой системы (обычно репозиторий и `~/.config` на одном разделе внутри `$HOME` — это не проблема). Если вдруг ФС разные, скрипт сам заметит это и сделает обычную копию вместо hardlink'а, с предупреждением в лог — но тогда правки перестанут синхронизироваться автоматически.

## Что руками, вне этого скрипта

- Раскомментировать `[multilib]` в `/etc/pacman.conf` — setup.sh только напоминает об этом текстом
- `chsh -s $(which zsh)` — смена дефолтного шелла спросит пароль и её проще сделать руками одной командой после первого запуска
